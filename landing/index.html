The activity log

Five kinds of change. One place they all land.

Move a card, check a subtask, post a comment — each one writes a row with the actor, a readable message, and the payload of what changed.

Questions

Before you open the board.

What happens when I continue as guest?+
A guest session is issued and a workspace is seeded with example tasks, so the board has something in it. You can drag, filter, comment and open the analytics view. Guests can't change roles or delete other people's work.
How do the four roles differ?+
Admins manage people and can delete accounts, managers run projects and assign work, members own their tasks, guests are read-mostly. Every role is checked on the server, so a hidden button is never the only thing standing between someone and an action they shouldn't take.
When does Pyramid notify someone?+
Assigning a task, moving it between columns, or commenting on it notifies the task's assignee and its creator. Your own actions never notify you. Everything lands in the bell with an unread count, and can be marked read or dismissed.
Is anything lost when a task changes?+
No. Each change writes an activity row with the actor, a readable message and a JSON meta payload of what changed. Read the trail workspace-wide, per project, or for a single task.
What is it built on?+
Next.js 16 with the App Router and React 19 on the front, a NestJS API behind it with Prisma over SQLite, JWT bearer sessions and role guards on protected routes. Styling is Tailwind v4 over CSS-variable themes — which is how four full palettes cost one token file.
Can I run it myself?+
Yes. One repository holds the web app and the API side by side with a SQLite file for the database, so npm run dev in each is the whole setup.
